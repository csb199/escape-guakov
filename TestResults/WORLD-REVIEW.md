# 场景与实体扩展 Review

本次将玩法场景移入签名资源包，增加同一流程内的实体挂载和独立空闲缓存策略。审查范围包括 Core、Unity 适配、流程调用、发布工具、Demo、自检与交付脚本，按 Unity 主线程上的频繁生成/回收和流程切换检查；没有把 Demo 数量当成大规模性能证明。

## 已修复的问题

1. **客户端仍将玩法场景内置。** 仅改 EditorBuildSettings 不够，BuildPlayerOptions 仍可显式传入三个场景。已将两处都限制为 Boot，Demo 验证 sceneCountInBuildSettings=1，并检查实际加载的包场景标记与路径。

2. **父回收可能遗漏刚挂载的子实体。** Transform 适配回调可以请求父回收；若此时图还未提交，父看不到子。现在先提交图，再调用适配器；失败拆除关系并回收失败子实例。核心测试覆盖适配回调内 RequestHide(parent)。

3. **换父回调可能关闭新的父节点。** Detach 回调允许 RequestHide，目标父已进入隐藏后若仍继续挂载，会绕过父隐藏时的子任务快照。已在 DetachCore 后重新验证两个端点；新增回归在修复前复现失败，修复后通过。证据：`scene-entity-reentry-before.log`、`scene-entity-core.log`。

4. **业务销毁回调重入缓存维护。** OnDestroy 再次释放缓存可能重复选中当前项，或在 Stop 枚举时修改字典。现在先移除全部候选，Stop 先快照并清空缓存，再调用业务钩子；聚合异常并结束共享关闭任务。回归覆盖 OnDestroy 内 ReleaseAllUnused。

5. **Unity 延迟 Destroy 与包卸载时序不安全。** 单次 Task.Yield 可能同帧恢复；单纯等待下一帧又可能遇到其他对象在恢复帧才释放。现在 Trim 等待 frameCount 变化，并保留本帧新归还租约的包，Stop 也跨帧后才能 Dispose。Demo 增加等待期间归还租约的验证，既有租约保护、卸载重载与并发关闭测试继续执行。

6. **自动淘汰与测试的旧假设冲突。** config 包可能已被周期维护卸载，“本次必须卸载至少一个包”的断言不成立。改为验证 config 已卸载且 shared 仍受活动租约保护，检查实际行为而非一次维护的计数。

## 所有权与架构检查

- 场景取消等待不能中止的 Unity 原生操作，再补偿卸载；场景卸载完成才释放包租约。失败保留租约，不越过仍使用资源的场景继续清理。
- 流程最早登记场景，逆序清理先释放实体、UI、音频；Result 取得自己的场景，不访问旧 Battle 的所有权。ModuleHost 的资源模块最后停止。
- 父子实体仅限同 owner，拒绝环、旧句柄与回调重入改图。父隐藏迭代预留整树任务、传播取消，等待子先完成；子任务不能等待祖先回收。
- 活动容量与空闲缓存目标独立。自动淘汰保护活动/锁定对象，按过期、优先级、最近使用时间排序并限制释放数量；最终 Stop 强制清理锁定缓存。
- owner/group 成员和实例索引避免每帧扫所有实体；仅当前流程 owner 更新。维护驱动按周期工作，不把业务逻辑放进 ModuleHost 全局轮询。
- V3 由冻结基线独立发布，包路径、场景内容与包哈希一并验证。客户端发布能力约束仍适用，场景资源本身不替代 AOT 兼容验证。

## 结论与证据

本轮已发现的正确性问题均已修复；最终构建与运行验证结果记录在 [WORLD-VALIDATION](WORLD-VALIDATION.md)。当前审查没有遗留必须修复项。

未验证真实万实体帧率、长时间频繁切换压测、移动平台或真实 CDN。缓存数量不是字节级内存预算，批量创建仍需业务分帧；跨流程实体转移、加载优先级队列不在本次实现范围。
