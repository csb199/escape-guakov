# 五项框架扩展 Review

本次增加独立热更发布、更新缓存预算、UIForm 生命周期、多包资源依赖和音频服务，并接入完整 Demo。模块由 ModuleHost 管生命周期，流程由 FSM/Procedure 编排，窗口、实体和音频通过各自作用域与资源租约管理所有权。

审查日期：2026-11-03。范围为本轮新增/修改源码、发布/验收脚本，以及 ModuleHost、FSM、Entity、传输和原子存储等相关调用链。按 Windows 单机小型游戏、主线程异步交错的实际使用方式评估。

工程没有 Git/SVN 工作副本，差异基于 `LocalOnly/Before-Framework-Expansion` 源码快照；变更清单为 `expansion-changes.txt`。采用 ponytail-review 的正确性、安全、规模、测试与复杂度检查。未加载 SVN 专项私有章程/常见错误资料，本次以本工程现有契约、Unity 行为和实测证据为准。

## 发现并修复

### 1. [P1，已修复] IL2CPP 无法查询磁盘空间

- **场景：** 下载前计算磁盘预算，原实现构造 DriveInfo。
- **问题：** Windows IL2CPP 实际启动抛出 `DriveInfo.GetDriveFormat` 不支持异常，首次安装无法继续。
- **修复：** Runtime 增加 `PlatformDiskSpace`，Windows 使用 GetDiskFreeSpaceExW；Bootstrap 注入查询函数，Core 保持可测试的独立实现。
- **验证：** 实际 IL2CPP 首次安装、升级、修复与重试均经过该检查；没有关闭磁盘预算来绕过失败。

### 2. [P1，已修复] Editor 主窗口缺少 Canvas

- **场景：** UI 预制体只有 RectTransform，打开时按需添加 Canvas/CanvasScaler。
- **问题：** Unity Editor 的缺失组件对象具有特殊空值语义，`GetComponent<T>() ?? AddComponent<T>()` 未触发添加，随后抛出 MissingComponentException。
- **修复：** 使用 Unity 的 `== null` 判断，并扫描全部 GetComponent/?? 调用，仅两处需要替换。
- **验证：** Editor Play Mode 的完整 46 项检查与清理通过；播放器使用同一修复源码重新构建。

### 3. [P1，已修复] 独立发布基线导出失效或错误拒绝兼容代码

- **场景：** 连续编译 V1、V2，再在客户端构建后导出基线；以后使用 V3 宏编译热更。
- **问题：** Unity 会替换之前 CompilePlayerScripts 的临时输出；另外编译宏会改变 AOT DLL 构建标识，原始文件哈希不能准确表示代码是否相同。
- **修复：** 及时快照编译结果；通过 dnlib 保留 IL、元数据、属性与资源，仅规范化构建 ID、时间戳和调试记录，再计算 AOT 指纹。裁剪元数据继续使用原始文件哈希。
- **验证：** 构建后成功导出冻结基线，独立发布 V3 并实际升级，EXE 和 GameAssembly 哈希保持不变；不匹配的基线被拒绝。

### 4. [P1，已修复] 泛型引用与 AOT 集合检查不完整

- **场景：** 新热更加入外部泛型实例化、原生声明，或项目新增 AOT 程序集。
- **问题：** 只检查普通成员/类型引用不能覆盖 MethodSpec/TypeSpec，遍历旧文件也不能发现新增 AOT DLL；把 V2 引用无条件加入白名单还可能超出 V1 客户端生成范围。
- **修复：** 纳入泛型实例化和原生声明，要求 AOT 程序集集合一致；V2 引用必须包含在生成客户端的 V1 范围内，不能扩张冻结白名单。
- **验证：** 核心测试检查新增引用、额外 AOT、AOT 修改、引擎变更拒绝；完整 BuildHybrid 执行 V1/V2 引用约束，独立 V3 发布通过同一检查。

### 5. [P2，已修复] staging 垃圾文件低估下载预算

- **场景：** 目标 staging 中残留与新版本无关的文件。
- **问题：** 直接从所需下载量扣除整个 staging 大小，会把垃圾字节当成已下载的有效内容，允许实际空间不足时继续下载。
- **修复：** 保守预留整个签名包及清单余量，现存 staging 单独计入占用，不抵消下载需求。
- **验证：** 注入无关暂存文件及不足预算，StageAsync 在下载前拒绝，不提交 pending，也不删除受保护的下载目录。

### 6. [P2，已修复] 关闭遗漏排队中的资源卸载

- **场景：** TrimUnusedAsync 等待资源锁时，资源模块同时停止并准备 Dispose。
- **问题：** 卸载原先不计入在途操作，且没有链接模块取消，可能在资源锁释放后继续操作已关闭服务。
- **修复：** Trim 与加载共同计入 pending，链接 lifetime；Stop 等待持锁操作和已取消的排队操作完成。
- **验证：** Demo 使用独立服务同时提交两次 Trim 后停止，断言两任务完成、pending 为零，再 Dispose。

### 7. [P2，已修复] 音频淡出不响应静音

- **场景：** 声音正在淡出，玩家同时关闭主音量或静音分组。
- **问题：** 原实现冻结淡出开始时的音量，并跳过正在停止的实例，声音可能继续发出。
- **修复：** 淡出作为独立乘数，每帧与主/组/实例音量组合；设置变化即时应用到正在淡出的声音。
- **验证：** 真实 AudioSource 淡出期间设置主静音，检查有效音量立即为零；重复停止只释放一次租约。

### 8. [P2，已修复] UI 初始化与清理边界

- **场景：** 激活的预制体含 OnEnable 行为，或 Cover/Reveal 中重入开窗，或一个窗口关闭抛错。
- **问题：** 直接 Instantiate 可能早于数据注入触发 OnEnable；回调重入可能覆盖新的层级计算；关闭异常可能跳过等待其他操作。
- **修复：** 在不激活的 staging 父节点下实例化，OnOpen 完成后显示；层级计算使用重入标记与快照；模块关闭先收敛各窗口和操作，再聚合错误。完成子资源注销父作用域登记，避免持续播放积累清理回调。
- **验证：** Demo 覆盖弹窗遮挡/恢复、打开中取消、延迟任务关闭、factory 失败、租约归还；核心测试检查清理登记注销。任意用户自定义 OnEnable/Cover/Reveal 行为未穷举。

## 架构结论

- Procedure 组织游戏状态，UiFormLogic/EntityLogic 处理自身行为，AudioService 管播放；职责仍分离。
- 依赖方向保持 Contracts → Core → Runtime 的使用关系；HotUpdate 使用稳定服务，Bootstrap 不引用业务程序集。
- ModuleHost 不轮询模块。FSM 只更新当前就绪流程；AudioDriver 只检查当前播放实例。
- 资源懒加载与依赖闭包引用计数符合当前五包需求，错误类型与取消请求不增加租约；当前串行加载避免重复加载竞态。
- 关闭等待已登记任务后才释放对象，重复关闭共享任务，旧句柄不恢复使用权。没有通过跳过等待来解决退出死锁。
- 发布工具与运行时更新职责独立，固定客户端基线和签名信任没有被业务发布流程覆盖。

**结论：本轮范围内的已确认阻断问题均已修复，最终验收已通过，可交付。** 最终构建标识、测试数量、源码一致性及报告目录见 [本轮验收](EXPANSION-VALIDATION.md)。

## 明确边界与未检查项

- 兼容白名单是保守的静态检查，不证明任意反射、动态泛型和运行时行为安全；新增稳定层 API、桥接或平台支持须重新构建客户端。
- 主线程约定下支持异步交错，没有声明任意多线程并发访问服务；不合作且永不完成的任务仍会阻止安全关闭。
- 缓存上限作用于当前客户端指纹，旧客户端目录未自动清除；预算检查不是操作系统级磁盘预留。
- 验证包含 Windows Editor/IL2CPP、自动游戏操作和截图检查；未做人耳音质验收、长时间压力测试、真实 CDN/生产签名流程以及 Android/iOS/WebGL 验证。
- 未加入音频混音器、暂停/3D 跟随、资源并行调度、UI 实例池等本次未要求的功能。
